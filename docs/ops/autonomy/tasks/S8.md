### Правила (владельца, 1–4)

1. **Разделение.** Клиентская квота — `apps/web/src/lib/selena-monthly-allowance.ts` (`monthlyAnswerUsage`, `monthlyAllowanceAdmits`), читается одной функцией `readMonthlyAnswerUsage` (`apps/web/src/server/selena-monthly-allowance.ts`) и в отчёте, и в столе заказов. Расход провайдера — отдельная величина из `sv_cost_events`, только у оператора.
2. **Неуспешные попытки не списывают квоту.** `used` = число запусков `sv_runs.status = 'SUCCEEDED'` в циклах месяца. `FAILED` и `INVALID` — нет.
3. **Частичный цикл не обнуляется.** Считаются его успешные запуски, каким бы ни был статус цикла (`QC_REQUIRED`, `STOPPED`, `FAILED`, `CARDINALITY_INCIDENT`). Исключение прежнее — заказ `CANCELLED` (оператор нажал «Stop»): он не считается целиком.
4. **Повторы и гонки.**
   - Повтор одной попытки: хранилище запусков уже идемпотентно (`runs.complete` возвращает запись, если `finishedAt` стоит; повторный `claim` отдаёт тот же run с `claimed: false`; `dispatch_key` уникален). Квота считает строки `sv_runs`, поэтому повтор не даёт второго `SUCCEEDED`. Проверено на живой БД (тест «does not charge a redelivered completion twice»).
   - Параллельные заказы: проверка идёт под `pg_advisory_xact_lock('selena-monthly-allowance:' || projectId)` внутри транзакции заказа; к `used` прибавляется `reserved` — незавершённые запуски идущих циклов (`expected − completed` для `CREATED/APPROVED/QUEUED/RUNNING/ANALYZING`) и `expectedRuns` блокировки оплаченных заказов без цикла (`PAID_REVIEW_REQUIRED/APPROVED/PREFLIGHT_BLOCKED/BUDGET_BLOCKED/PROVIDER_BLOCKED`). Второй из двух одновременных заказов на остаток месяца получает отказ (тест «lets only one of two simultaneous orders…»).

### Изменение контрактных правил (вынесено и в описание PR)

- Ранее: квота = сумма `expectedRuns` всех циклов месяца, кроме исключённых статусов; неудачный цикл выпадал только после «Stop». Теперь: квота = успешные ответы + зарезервированные; статусы `FAILED/CARDINALITY_INCIDENT/STOPPED` цикла больше ничего не исключают сами по себе (их успешные ответы считаются, правило 3).
- Ранее заказы, ожидающие оператора, не учитывались до создания цикла («operator's call»). Теперь их объём резервируется. Интерпретация: без этого два параллельных заказа проходят проверку оба.
- `monthlyAnswerAllowance` (число 300/800/2000) не менялся. ACCEPTANCE.md и PROMISES.md пунктов о механике списания не содержат; правило записано в `docs/selena-visibility/REPORT_DESIGN_SPEC.md` (раздел «месячный запас ответов»).
- Миграций нет: обе величины считаются из существующих таблиц.
